# 철칙 #4 게이트가 왜 안 걸렸나 — 2026-08-25

## 질문

`fx_guard_overedit` 가 변경률 0.617 로 강제중단 상한 0.50 을 넘겼다. SKILL.md
Phase 2.5 는 "exit 2(문자율 ≥50%)면 **윤문본 채택 금지**, 롤백 재실행 1회"라고
못박고 있다. 그런데 0.617 짜리 윤문본이 그대로 돌아왔다.

두 가지가 가능했고 처방이 완전히 다르다.

- **게이트가 안 돈다** → 배선 문제
- **돌고도 무시한다** → 순응 문제

## 방법

`claude -p --output-format stream-json --verbose` 로 같은 fixture 입력을 윤문시키고
**실제 호출된 도구를 셌다.** 조건 둘, 각 1회.

- 실험군: 테스트 러너(`tests/humanize_runner.py`)의 프롬프트 그대로
- 대조군: 거기서 **"파일은 만들지 마"** 한 구절만 뺀 것

## 결과

| | 도구 호출 | Bash | 게이트 스크립트 | 변경률 |
|---|---|---|---|---|
| 실험군 (러너 프롬프트) | 2회 | **0회** | 없음 | 0.617 |
| 대조군 (파일 금지 제거) | 8회 | 5회 | `prepare_monolith_input.py --help` 까지만 | 0.667 |

실험군이 부른 것은 둘뿐이다 — `Skill: humanize-korean`, `Read: quick-rules.md`.
**Bash 가 한 번도 안 돌았으므로 Phase 2.5 는 시작조차 안 했다.**

## 판정 — 안 돈다. 그것도 두 층에서

**층 1. 테스트 하네스가 자기가 검증하려는 기제를 끄고 있다.**
러너 프롬프트의 "파일은 만들지 마"가 게이트를 통째로 죽인다(Bash 0회 대 5회).
Phase 2.5 는 `_workspace/` 에 입력을 쓰고 스크립트를 돌리는 파일 기반 단계라, 파일
생성을 금지하면 존재할 수 없다. 즉 `fx_guard_overedit` 는 **"스킬이 가드를 지키는가"가
아니라 "모델이 가드 없이 얼마나 자제하는가"를 재고 있었다.** 8일 동안 붉었던 이유가
여기 있고, 그 붉음은 fixture 가 의도한 것과 다른 것을 가리키고 있었다.

**층 2. 금지를 풀어도 게이트는 완주하지 않는다.**
대조군은 워크스페이스를 만들고 `01_input.txt` 를 쓰고 `prepare_monolith_input.py --help`
까지 갔지만, **`verify_gates.py` 도 `verify_change_rate.py` 도 부르지 않았다.** 준비만 하고
검증 스텝을 건너뛴 채 0.667 짜리 결과를 냈다. 파일 금지는 원인의 전부가 아니다.

## 그래서 고칠 것 둘

1. **하네스**: 러너 프롬프트에서 파일 금지를 빼거나, 게이트를 테스트가 직접 돌린다.
   지금 형태로는 이 fixture 가 무엇을 재는지 이름과 실제가 어긋난다.
2. **스킬**: Phase 2.5 가 실제로 실행되도록 강제한다. 준비 스크립트까지 가고 검증에서
   멈추는 것이 재현되는지부터 표본을 늘려 확인할 것.

## 재현 확인 — n=5 로 다시 쟀다 (2026-08-25 후속)

층 2 가 1회 관찰이었으므로 대조군 프롬프트(파일 금지 없음)로 4회를 더 돌려 5회로 만들었다.

| run | Bash | `verify_gates.py` 실행 | `prepare_monolith_input.py` 실행 | 변경률 | 가드 초과 |
|---|---|---|---|---|---|
| 1 | 5 | **0** | 1 | 0.667 | 예 |
| 2 | 3 | **0** | 0 | 0.530 | 예 |
| 3 | 3 | **0** | 0 | 0.655 | 예 |
| 4 | 7 | **0** | 0 | 0.489 | 아니오 |
| 5 | 5 | **0** | 1 | 0.414 | 아니오 |

**게이트 스크립트 실행 0/5.** 층 2 는 확정됐다 — 파일 금지를 풀어도 게이트는 실행되지 않는다.
`prepare_monolith_input.py` 조차 2/5 다. 즉 스킬이 워크스페이스 파이프라인 전체를 건너뛰고
`quick-rules.md` 만 읽고 바로 다시 쓴다.

**왜 그러는지는 SKILL.md 를 보면 짐작이 간다.** Phase 2.5 의 실행 명령은 존재한다:

```
python3 ${SKILL_ROOT}/scripts/verify_gates.py \
    --before _workspace/{run_id}/01_input.txt \
    --after  _workspace/{run_id}/final.md --genre {genre}
```

그런데 이 명령은 **워크스페이스 파일 둘을 전제한다.** 308자짜리 짧은 입력에서 스킬은
워크스페이스를 안 만들고 바로 고쳤고, 그러면 게이트가 가리킬 파일이 없다. 명령이 없어서가
아니라 **명령의 전제가 없어서 안 돈다.** (이것은 추론이고 스킬에게 이유를 물어 확인한 것은 아니다.)

변경률은 0.414~0.667 로 흩어지고 3/5 가 가드를 넘는다. fixture 의 참조 출력이 0.481 이니
이 입력은 **상한 바로 위아래를 오가는 경계 표본**이다. K=3 전원 통과를 요구하면 게이트가
고쳐지더라도 자주 붉을 것이다.

## ⚠️ 이 문서가 한 번 스스로를 뒤집을 뻔했다 — 계수기 결함

n=5 를 처음 집계했을 때 "게이트 실행 4/5"가 나왔고, 나는 층 2 가 기각됐다고 판단했다.
**계수기가 틀렸다.** 명령 문자열에 `verify_gates.py` 가 들어 있으면 실행으로 셌는데,
그중 넷은 `ls .../verify_gates.py` — **존재 확인**이었다. 실제로 파이썬이 부른 것으로
좁히니 0/5 였다.

같은 데이터로 정반대 결론이 나왔다. 볼트 규칙의 "측정기 ≠ 진실"이 여기 그대로 걸린다 —
**검증기 통과·실패를 액면으로 받지 않고 반례를 먼저 찾는다.**

부수적으로 변경률 추출기도 틀렸었다. 어시스턴트가 지시문을 되뇌며
`<<<H>>> 와 <<</H>>>` 라고 쓰면 정규식의 첫 매치가 `'와 '` 가 되어 변경률이 1.0 으로
나온다. 가장 긴 매치를 쓰도록 고쳤다.

## 그래서 고칠 것 둘 (수정 없음)

1. **하네스**: 러너 프롬프트에서 파일 금지를 빼거나, 게이트를 테스트가 직접 돌린다.
   ⚠️ 이 층은 여전히 **n=1** 이다(Bash 0회 대 5회). 기제는 명확하지만 반복은 안 했다.
2. **스킬**: Phase 2.5 가 워크스페이스 파일에 의존하지 않게 하거나, 짧은 입력에서도
   워크스페이스를 반드시 만들게 한다. 지금은 짧은 글일수록 가드가 없다.

## 재현

```bash
env -u ANTHROPIC_API_KEY claude -p --output-format stream-json --verbose "<프롬프트>" \
  </dev/null > trace.jsonl
```

- 게이트 실행 판정은 `python3?\s+\S*verify_gates\.py` 로 **좁혀서** 센다. 파일명만 찾으면 `ls` 가 섞인다.
- 윤문본은 센티넬 매치 중 **가장 긴 것**을 쓴다.

⚠️ `--verbose` 없이 `--output-format stream-json` 만 주면 도구 호출이 안 보인다.
⚠️ `result` 레코드가 나오기 전에 파싱하면 도구가 0회로 보인다 — 프로세스 종료를 먼저 확인할 것.
